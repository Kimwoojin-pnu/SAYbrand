Trust & Safety

보안 정책

SAYbrand가 고객 데이터를 보호하는 방법을 설명합니다.

데이터 암호화

🔒

전송 구간 암호화

모든 데이터는 TLS 1.2 이상으로 암호화되어 전송됩니다. HTTP 연결은 자동으로 HTTPS로 리다이렉트됩니다.

🗄️

저장 데이터 보호

데이터베이스는 AES-256 암호화가 적용된 클라우드 환경에 저장됩니다. 비밀번호는 bcrypt 해시로만 저장되며 원문은 보관하지 않습니다.

🔑

API 키 보안

외부 API 키(Gemini, Claude, Naver 등)는 환경변수로 관리되며 코드베이스에 포함되지 않습니다. 키는 정기적으로 교체됩니다.

접근 제어

👤

역할 기반 접근 제어 (RBAC)

조직 내 역할(Admin / Member / Viewer)에 따라 데이터 접근 권한이 분리됩니다. Viewer는 읽기 전용, Member는 제한적 쓰기, Admin은 전체 관리가 가능합니다.

🛡️

세션 관리

세션은 서버 사이드에서 관리되며 브라우저 종료 시 만료됩니다. 비정상 접근 패턴이 감지될 경우 세션이 자동 무효화됩니다.

⏱️

속도 제한 (Rate Limiting)

API 엔드포인트에 요청 횟수 제한이 적용되어 무차별 대입 공격 및 과부하를 방지합니다.

인프라 보안

☁️

클라우드 인프라

서비스는 Vercel(엣지 네트워크), Railway(데이터베이스), Redis Cloud(캐시)를 사용합니다. 각 서비스는 SOC 2 Type II 또는 ISO 27001 인증을 보유하고 있습니다.

🌐

데이터 격리

조직(Organization)별 데이터는 DB 레벨에서 org_id로 격리됩니다. 타 조직의 데이터에 접근할 수 없도록 모든 쿼리에 조직 필터가 적용됩니다.

보안 모니터링 및 대응

회사는 다음과 같은 보안 모니터링 체계를 운영합니다.

  • 서버 에러 및 이상 트래픽 실시간 모니터링
  • 보안 사고 발생 시 72시간 이내 영향을 받은 이용자에게 통지
  • 정기 의존성 패키지 취약점 점검 및 업데이트
  • 코드 변경 사항에 대한 보안 리뷰

보안 취약점 신고

SAYbrand 서비스에서 보안 취약점을 발견하셨나요? 책임감 있는 취약점 공개(Responsible Disclosure)를 환영합니다.

신고 방법: security@saybrand.ai 로 이메일 신고

포함 내용: 취약점 설명, 재현 방법, 예상 영향 범위

처리 기간: 접수 후 48시간 이내 확인, 심각도에 따라 우선 처리

참고: 악의적 이용 또는 서비스 방해 행위는 법적 조치 대상이 될 수 있습니다.

보안 정책 업데이트

이 보안 정책은 서비스 변경 또는 보안 체계 개선에 따라 업데이트될 수 있습니다. 중요한 변경 사항은 서비스 내 공지 또는 이메일로 안내드립니다.

보안 관련 문의: 고객센터 또는 security@saybrand.ai
